## CSE 321 — 1 Introduction

The calculation chain has three levels: assessment grade → (by percentages) Learning Outcome (LO) → (by 1–5 weights) PO. Every level uses the same formula: `score = Σ(weight × score) ÷ Σ weight`. The acceptance test is the instructor's example: for Midterm 90 and Project 80 the system produces LO1 = 86.0, LO2 = 82.9, PO1 = 85.0, PO2 = 82.9 (a unit test, and the `elif` user in the demo data).

Today permissions are model-level in the Django admin; the "an instructor sees only their own course" check and the student dashboard do not exist yet.

## CSE 321 — 2 System Design

**Architecture (Figure 1).** The system is a single Django application server: a request passes through the URLs and settings under `config/` and reaches the models and the calculation service in the `outcomes/` app. External components are selected in `config/settings.py` through environment variables; if a variable is not set, a local fallback is used.

| Component | Purpose | Variable | Fallback | Current state |
|---|---|---|---|---|
| PostgreSQL | Persistent data | `POSTGRES_DB` | SQLite | In use; tests pass on PostgreSQL 18 |
| Redis | Cache for report queries | `REDIS_URL` | In-process memory | Configured; no query is cached yet |
| SMTP | E-mail notifications | `EMAIL_HOST` | Console | Configured; no feature sends e-mail yet |
| File storage | Excel/CSV, syllabus PDF | `MEDIA_ROOT` | `./media` | Configured; no upload screen yet |

**Classes (Figure 2).** The code has three parts: models (`models.py`), the calculation service (`services.py`) and triggers (`signals.py`).

| Class | Responsibility |
|---|---|
| `User`, `Course`, `Enrollment`, `LearningOutcome`, `ProgramOutcome` | Institutional structure: who, which course, which outcome |
| `Assessment`, `StudentGrade` | Assessments and raw grades |
| `Assessment_LO_Mapping`, `LO_PO_Mapping` | Weights: assessment → LO (coefficient), LO → PO (1–5) |
| `StudentPOSnapshot` | Precomputed PO profile; written only by the service |
| `POCalculatorService` | Grade → LO → PO calculation, snapshot writes, finding affected students |
| `signals` | Call the service when a grade, mapping or weight changes |

The formula lives in a single function (`weighted_average`) used at both levels; when the total weight is 0 it returns `None` (no data), not 0. Example: LO1 = (0.60 × 90 + 0.40 × 80) ÷ 1.00 = 86.0; LO2 = (0.40 × 90 + 1.00 × 80) ÷ 1.40 = 82.9; PO1 = (2 × 86.0 + 1 × 82.86) ÷ 3 = 85.0; PO2 = 82.9. The instructor's 1.0 : 0.5 : 1.0 weights are entered as 2 : 1 : 2 because the model stores integer weights from 1 to 5; the result is the same.
